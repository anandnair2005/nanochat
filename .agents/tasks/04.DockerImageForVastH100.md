## Agent Objective
Add Docker build files for an H100-ready nanochat image that contains the repo code, Python 3.10 environment, GPU dependencies, and operational tools needed by Vast.

## Files To Create Or Modify
- Create `Dockerfile.vast-h100`.
- Create `.dockerignore` if it does not exist.
- Optionally create `runs/docker_build_vast_h100.sh` for reproducible local builds.
- Do not bake datasets, checkpoints, rclone credentials, wandb tokens, Vast API keys, `.env`, or local run manifests into the image.

## Required Behavior
- Install system tools needed by the workflow: `curl`, `git`, `openssh-server`, `tmux`, `screen`, `rsync`, `rclone`, and basic diagnostics where reasonable.
- Install `uv`.
- Copy repo code into a stable path such as `/workspace/nanochat`.
- Run `uv sync --extra gpu` during image build.
- Make the runtime working directory the repo root inside the image.
- Ensure `runs/prewarm_vast.sh`, `runs/speedrun_vast.sh`, and sync/startup scripts are executable if they exist.
- Set a default command or entrypoint that is compatible with Task 05 once implemented.

## Implementation Constraints
- Prefer a CUDA/PyTorch base image compatible with `torch==2.9.1` and CUDA 12.8.
- Do not attempt to support Apple Silicon MPS in this H100 image.
- Keep the image focused on Vast H100 execution.
- Keep build args minimal and documented.
- `.dockerignore` must exclude cache directories, checkpoints, datasets, `.env`, wandb data, and local manifests.

## External Tools Required
- Docker daemon with build support.
- Network access to package indexes and base image registry.
- Container registry access only if pushing is part of the execution.
- No MCP server is required.
- A Docker MCP can help inspect images, but normal Docker CLI is sufficient.

## Commands To Run
- `docker build -f Dockerfile.vast-h100 -t nanochat-vast-h100:test .`
- `docker run --rm nanochat-vast-h100:test python -c "import torch; print(torch.__version__)"`
- `docker run --rm nanochat-vast-h100:test bash -lc 'command -v uv && command -v rclone && command -v tmux'`

## Acceptance Criteria
- Dockerfile and `.dockerignore` exist.
- The image builds successfully when Docker is available.
- The image contains the repo, `.venv`, `uv`, `torch`, `rclone`, and `tmux`.
- The image does not include obvious local caches, datasets, checkpoints, or secrets.
- If Docker is unavailable, the agent must stop after file creation, state that build verification could not run, and list the exact commands for the user to run.

## Stop And Ask If
- Docker is unavailable and the user requires image build verification in this task.
- The selected base image cannot satisfy CUDA/PyTorch compatibility.
- A private registry push is required and credentials are not available.
