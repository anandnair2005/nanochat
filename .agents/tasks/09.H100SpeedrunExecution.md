## Required Behavior
- Add a command or mode that waits for a manually created H100 instance.
- Require `--run-id`, storage volume discovery, and SSH connection details derived from Vast CLI.
- Require preflight success or a `--skip-preflight` override.
- Verify the prewarmed storage contains `base_data_climbmix` and tokenizer artifacts before launch when possible.
- Configure H100 environment variables for the SSH-launched tmux command: `NANOCHAT_BASE_DIR`, `NANOCHAT_SKIP_UV_SYNC=1`, `NANOCHAT_SKIP_DATASET=1`, `NANOCHAT_SKIP_TOKENIZER=1`, `NANOCHAT_RUN_ID`, `WANDB_RUN`, `NANOCHAT_ENABLE_GDRIVE_SYNC=1`, and sync-related variables.
- Record detection time, instance ID, image tag if available, and env/config summary in the manifest.
- Monitor instance state and status markers until success, failure, timeout, or user interruption.
- Do not treat container exit alone as successful completion.

## Implementation Constraints
- Do not create or select the H100 instance; the user creates it manually through Vast CLI or portal.
- Do not put broad Vast API credentials inside the H100 container.
- Do not hardcode a specific Vast offer.
- Default to preserving resources on ambiguous failure unless cleanup policy says otherwise.
- Do not run the full H100 speedrun during normal automated tests.

- Prewarmed Vast storage.
