# Task 12: Implement Run Documentation And Blog Artifact Generator

## Status
Pending.

## Completion Notes
- Not implemented yet.
- Run summary/blog artifact generator is still pending.

## Agent Objective
Create tooling that turns a completed or failed Vast speedrun manifest into a human-readable run summary suitable for later blog writing.

## Files To Create Or Modify
- Create `tasks/render_run_summary.py` or equivalent.
- Optionally create `docs/run_summary_template.md`.
- Modify the orchestrator only if needed to call the summary generator at the end.
- Do not include secrets in generated summaries.

## Required Behavior
- Read a run manifest produced by the local orchestrator.
- Read available local logs and status markers when paths are present.
- Generate `summary.md` under the run directory, for example `.agents/runs/<run-id>/summary.md`.
- Include git commit SHA and dirty worktree status if captured or available.
- Include Docker image tag/digest if present.
- Include Vast resource IDs, selected offer metadata, GPU count/type, storage size, and timing if present.
- Include prewarm, H100 execution, sync, and cleanup phase durations if present.
- Include estimated costs if present in manifest.
- Include Google Drive/rclone archive path.
- Include links or paths to `report.md`, logs, checkpoints, and generated samples when known.
- Redact secret-like values.
- Clearly distinguish upstream nanochat behavior from local Vast-specific customization.

## Implementation Constraints
- Keep the generator local and file-based.
- Do not require Google Drive credentials to render a summary.
- Do not upload or publish anything.
- Use only standard library Python unless a dependency already exists in the repo.
- If manifest fields are missing, render `unknown` rather than failing unless the manifest itself is unreadable.

## External Tools Required
- Python 3.10.
- Git CLI is useful for commit/worktree status if not already captured.
- No MCP server is required.
- A Google Drive MCP could help inspect archive contents, but summary generation should not depend on it.

## Commands To Run
- `python tasks/render_run_summary.py --help`
- Run the generator against a synthetic manifest committed as a small test fixture or created in `/tmp`.
- If tests are added, run the focused test command.

## Acceptance Criteria
- Summary generator exists and has help output.
- It can render a summary from a synthetic manifest without external services.
- Output redacts secret-like fields.
- Output includes implementation details useful for a blog: repo version, image, resources, phases, costs, archive path, artifacts, and customization notes.
- The final agent response points to the generated test summary.

## Stop And Ask If
- The user wants automatic publication to a blog platform.
- The user wants the summary to include private account or credential details.
- The manifest schema from earlier tasks is unavailable and cannot be inferred.
